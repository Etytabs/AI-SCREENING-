# ShakaHive Shared Resources & Progress Hub

This directory is the shared documentation area for technical and non-technical contributors. Keep records organised, link work to GitHub Issues and Projects, and never store secrets or unauthorised confidential applicant information here.

## Structure

```text
resources/
  meetings/       # agendas, minutes, actions
  decisions/      # product, business and operational decisions
  progress/       # weekly updates and milestone reports
  research/       # market, stakeholder and technical research
  reports/        # approved programme and pilot reports
  templates/      # reusable templates
  onboarding/     # team guides and contribution instructions
```

## Weekly update template

Copy `templates/weekly-update.md`. Each contributor records:
- What was completed (link issues/PRs/documents).
- What is in progress.
- Next week's commitments.
- Blockers, risks and help needed.
- Evidence, findings or decisions.
- Any changes to estimates or milestone dates.

## Meeting notes

Use `templates/meeting-notes.md`. Record date, attendees, agenda, decisions, actions, owners and due dates. Link each action to a GitHub Issue.

## Research record

Use `templates/research-note.md`. Record question, method, sources and dates, findings, assumptions, limitations, recommendation and follow-up action.

## Progress tracking

GitHub Projects is the live work tracker. This folder stores narrative reports and decision evidence; it is not a substitute for updating issue status.

## Contribution guidance

- Technical contributors document code, APIs, architecture, tests, model evaluations, deployments and incidents.
- Business contributors document customer discovery, market assumptions, partnerships, pricing research and commercial risks.
- Product/project contributors document requirements, user feedback, acceptance criteria, meeting decisions and milestones.
- All contributors link their work to a project item where possible.
